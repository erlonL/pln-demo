# Political Print Laboratory

**Version:** 1.0.0  
**Status:** Foundations  
**Updated:** 2026-08-25  
**Implementation baseline:** Semantic HTML and plain CSS

This document is the portable source of truth for the Political Print Laboratory design system. It is intentionally complete enough to use without this repository, its original source code, or its visual references. Framework adapters may wrap these rules, but must not redefine them.

## 1. North star

An intellectual political editorial system combining institutional clarity with confrontational scale and tactile print-process character.

The system should feel:

- intellectual, analytical, and credible;
- confrontational, psychological, and slightly sinister;
- tactile, underground, political, editorial, and experimental;
- physically printed and recombined, even when every element is generated by code.

The stable hierarchy is:

> Tiny institutional heading → massive emotional headline → restrained descriptive copy

The interface must retain its character when every photograph or illustration is removed. Images add subject matter; typography, composition, surfaces, and code-native material effects carry the art direction.

### Not this system

Do not introduce handwriting, arrows, circles, dates used as decoration, case numbers, evidence labels, underlines, scribbled observations, detective boards, or notebook marginalia. These change the visual language from political print editorial to investigative scrapbook.

Also avoid glossy gradients, glass panels, soft floating cards, diffuse colored glows, elastic motion, ornamental rounded rectangles, and generic dashboard composition.

## 2. Operating principles

1. **Hierarchy before texture.** A page must work in flat black, paper, and red before grain or halftone is applied.
2. **One dominant disruption.** A section may use one primary irregularity: overlap, hard crop, edge bleed, registration shift, or paper edge. Do not combine all five.
3. **Red has a job.** Signal red marks the dominant message, primary action, or critical state. It is not ambient decoration.
4. **Asymmetry stays on a grid.** Editorial tension comes from unequal spans and intentional overlap, not arbitrary absolute coordinates.
5. **Materiality is systematic.** Grain, halftone, clipping, and hard shadows are reusable variants with controlled intensity.
6. **Information remains legible.** Texture never crosses text at an intensity that weakens reading or contrast.
7. **Data color remains semantic.** Classification colors identify categories. They do not compete with brand red for visual dominance.
8. **Mobile is recomposed.** Editorial layouts become a deliberate reading sequence, not a miniaturized desktop.
9. **Motion is mechanical.** Controls press, rules reveal, layers register, and masks open. Elements do not float.
10. **The system is opt-in.** Product-specific styling may adopt the system incrementally without requiring a wholesale rewrite.

## 3. Composition grammar

### Editorial hierarchy

- An eyebrow is normally one or two short lines, uppercase, and set in metadata type.
- A display headline is approximately 2–8 words, preferably no more than two lines, with a maximum measure around `10ch`.
- Display leading stays between `0.82` and `0.90`; supporting copy uses `1.45–1.6`.
- Place the eyebrow close enough to read as institutional context, then allow the headline to dominate the viewport.
- Supporting copy usually stays between `45ch` and `68ch` and must remain visibly quieter than the headline.
- A section should have one obvious first read, one second read, and no more than one competing accent.

### Surface balance

- Choose carbon or warm paper as the dominant page surface.
- Use the opposite surface as an inserted editorial layer, not as a collection of generic cards.
- Signal-red surfaces should normally be one continuous block or one primary control in a viewport.
- Use a thin rule for ordinary separation and a 2px rule for focus, emphasis, or structural boundaries.
- Default radius is zero. Use 2px for practical controls and 6px only where clipping or platform convention requires it. Pills are reserved for compact tags.

### Motif budget

For each section, choose at most one:

- a one-column overlap;
- a hard edge bleed;
- a monochrome or duotone crop;
- a clipped paper edge;
- a 4–8px registration shadow;
- a large signal-red field.

Grain may be present across the page because it behaves as substrate rather than a motif. Keep it subtle.

### Spacing, sizing, and measures

The base step is 4px. Use only the following spacing tokens: `0`, `4`, `8`, `12`, `16`, `24`, `32`, `48`, `64`, `96`, and `128px`.

- Page gutter: `clamp(1rem, 3vw, 3rem)`.
- Default section spacing: `clamp(4rem, 9vw, 8rem)`.
- Compact section spacing: `clamp(2rem, 5vw, 4rem)`.
- Hero section spacing: `clamp(5rem, 12vw, 10rem)`.
- Summary measure: `45ch`.
- Body measure: `68ch`.
- Narrow container: `48rem`.
- Default container: `80rem`.
- Wide container: `96rem`.
- Compact control: `40px` high.
- Default control: `48px` high.
- Minimum touch target: `44 × 44px`.

### Grid and breakpoints

| Width | Columns | Expected behavior |
|---:|---:|---|
| Below 480px | 4 | Edge-aware single sequence; large type remains large |
| 480–767px | 4 | More breathing room; controlled edge bleed allowed |
| 768–1023px | 8 | Split layouts may activate |
| 1024–1439px | 12 | Full editorial grid and one-column overlap |
| 1440px and above | 12 | Wider outer margins; do not keep stretching copy |

Use `minmax(0, 1fr)` columns and a gap of `clamp(.75rem, 2vw, 1.5rem)`. Layout content must not depend on an exact viewport height.

### Borders, depth, and layers

- Thin rule: `1px`.
- Strong or focus rule: `2px`.
- Print shadow: `4px 4px 0` or `8px 8px 0` using red or ink.
- Avoid blurred decorative shadows. A native system popover may use platform elevation when required for usability.
- Layer scale: base `0`, texture `10`, content `20`, navigation `40`, overlay `80`, modal `100`.

### Motion

| Token | Duration | Use |
|---|---:|---|
| Instant | 100ms | Press or state confirmation |
| Control | 180ms | Hover, focus, tabs, toggles |
| Reveal | 320ms | Content entry or rule expansion |
| Editorial | 600ms | A single major masked reveal |

Preferred easing:

```css
--ds-ease-mechanical: cubic-bezier(.2, .8, .2, 1);
--ds-ease-snap: cubic-bezier(.3, 0, .2, 1);
```

Animate `opacity`, `transform`, or mask/clip progress. Do not animate layout size when a transform can communicate the same change. Texture stays stationary.

## 6. Layout primitives

All primitives are class-based, framework-independent, and prefixed with `ds-`. Product code may wrap them in components, but should preserve their semantics and responsive behavior.

### Shell, container, and section

- `.ds-shell` establishes the page surface, text color, body type, isolation, and minimum viewport height.
- Use `data-theme="paper"` for a paper-dominant page. Carbon is the default.
- `.ds-container` centers content at `80rem` with a fluid gutter.
- Use `data-width="narrow"` for forms or linear reading and `data-width="wide"` for editorial compositions.
- `.ds-section` supplies vertical rhythm. Its `compact` and `hero` density variants are the only supported alternatives.

```html
<main class="ds-shell ds-grain">
  <section class="ds-section" data-density="hero">
    <div class="ds-container ds-stack" data-width="wide" data-space="loose">
      <!-- page content -->
    </div>
  </section>
</main>
```

Do not apply a separate max-width to every child. Containers own horizontal page alignment; readable text elements own their character measure.

### Stack and cluster

- `.ds-stack` handles vertical flow and defaults to 24px spacing.
- `data-space="tight"` uses 12px; `data-space="loose"` uses 48px.
- `.ds-cluster` handles wrapping inline groups and defaults to a 12px gap.
- `data-justify="between"` is appropriate for toolbars with two meaningful groups, not arbitrary space distribution.

```html
<div class="ds-stack" data-space="tight">
  <p class="ds-eyebrow">Natural language processing</p>
  <h1 class="ds-display">Beyond words</h1>
  <p class="ds-copy" data-size="lead">A restrained explanation belongs here.</p>
</div>
```

### Grid and split

- `.ds-grid` creates 4 columns by default, 8 at 768px, and 12 at 1024px.
- `.ds-split` is one column below 768px and `5fr 7fr` above it.
- Use `data-ratio="7:5"` when the first region should dominate.
- Keep the reading-order DOM sequence correct. CSS must not be the only source of semantic order.

```html
<div class="ds-split" data-ratio="7:5">
  <div class="ds-frame" data-ratio="editorial">…</div>
  <div class="ds-stack">…</div>
</div>
```

### Editorial composition

`.ds-editorial` is the controlled-asymmetry primitive. It becomes a 12-column layout at 1024px:

- default: copy spans columns 1–6 and media spans columns 6–12, producing a one-column overlap;
- `data-order="media-first"`: media spans columns 1–7 and copy spans columns 7–12;
- below 1024px, it becomes a linear sequence with a 48px gap;
- overlap is limited to one column and must never obscure essential text or controls.

```html
<section class="ds-editorial">
  <div class="ds-editorial__copy ds-material ds-stack" data-surface="paper">
    <p class="ds-eyebrow">Institutional context</p>
    <h2 class="ds-display">A strong claim</h2>
    <p class="ds-copy">Supporting analysis remains calm and readable.</p>
  </div>
  <figure class="ds-editorial__media ds-frame" data-ratio="portrait" data-treatment="mono">
    <img src="subject.jpg" alt="Descriptive alternative text">
  </figure>
</section>
```

### Media frame

`.ds-frame` controls cropping and treatment:

| Attribute | Result |
|---|---|
| No ratio | 4:3 editorial crop |
| `data-ratio="square"` | 1:1 |
| `data-ratio="portrait"` | 4:5 |
| `data-ratio="wide"` | 16:9 |
| `data-treatment="mono"` | Grayscale with increased contrast |
| `data-treatment="duotone"` | Monochrome source with signal-red multiply layer |

Use `object-fit: cover`. Choose the crop deliberately with `object-position`; do not expose a different accidental focal point at each breakpoint. Text should not be baked into imagery.

### Bleed

`.ds-bleed` extends to the viewport-side container gutters below 768px and returns to normal width above that point. Use it for one significant surface or media block, not every section child.

## 7. Material primitives

### Surfaces

`.ds-material` defaults to ink and supports `paper` and `signal` surfaces. Add `data-elevation="print"` for a hard 8px registration shadow. Supply padding with a spacing token appropriate to the component; the material primitive does not guess content density.

```html
<aside class="ds-material ds-paper-edge ds-grain" data-surface="paper" data-elevation="print">
  <div class="ds-stack">…</div>
</aside>
```

### Grain

Grain simulates substrate, not dirt. Apply `.ds-grain` to a page shell or large surface, normally once per compositional layer. Default opacity is `0.055`; do not exceed `0.08` beneath text or `0.12` in a text-free decorative field.

### Halftone

`.ds-halftone` uses a 5px radial-dot pattern at 9% opacity. It works best on a large numeral, media field, or empty edge. Do not apply it over body copy, controls, or data labels.

### Paper edge

`.ds-paper-edge` provides a very shallow irregular clipping polygon. It communicates a cut or torn insert without becoming scrapbook decoration. Use it on at most one major paper layer per section.

Canonical material implementation:

```css
:root {
  --ds-texture-opacity: .055;
  --ds-halftone-size: 5px;
  --ds-texture-grain: url("data:image/svg+xml,%3Csvg viewBox='0 0 256 256' xmlns='http://www.w3.org/2000/svg'%3E%3Cfilter id='n'%3E%3CfeTurbulence type='fractalNoise' baseFrequency='.82' numOctaves='4' stitchTiles='stitch'/%3E%3C/filter%3E%3Crect width='100%25' height='100%25' filter='url(%23n)' opacity='.9'/%3E%3C/svg%3E");
}

.ds-grain,
.ds-halftone { position: relative; isolation: isolate; }

.ds-grain::before,
.ds-halftone::after {
  content: "";
  position: absolute;
  inset: 0;
  z-index: 10;
  pointer-events: none;
}

.ds-grain::before {
  background: var(--ds-texture-grain) 0 0 / 256px 256px;
  mix-blend-mode: soft-light;
  opacity: var(--ds-texture-opacity);
}

.ds-halftone::after {
  background-image: radial-gradient(circle, currentColor 0 1px, transparent 1.2px);
  background-size: var(--ds-halftone-size) var(--ds-halftone-size);
  opacity: .09;
}

.ds-grain > *,
.ds-halftone > * { position: relative; z-index: 20; }
```

These effects are decorative. They must use `pointer-events: none`, must not be announced by assistive technology, and must disappear in forced-colors mode.

## 8. Component contracts

These are implementation recipes, not mandatory framework components. Every implementation must derive its color, type, spacing, border, and motion from the shared tokens.

### Button

**Anatomy:** optional leading icon, label, optional trailing icon or loading indicator.  
**Sizes:** compact 40px; default 48px. Touch area must remain at least 44px.  
**Variants:** signal, ink, paper, ghost.  
**Shape:** square by default; 2px radius allowed.  
**Motion:** 2px translation on press, 100–180ms. Do not float upward or glow.

```css
.button {
  min-block-size: var(--ds-control-default);
  display: inline-flex;
  align-items: center;
  justify-content: center;
  gap: var(--ds-space-2);
  padding-inline: var(--ds-space-5);
  border: var(--ds-border-strong) solid var(--ds-color-carbon);
  border-radius: var(--ds-radius-xs);
  background: var(--ds-color-signal);
  color: var(--ds-text-on-signal);
  font: var(--ds-weight-semibold) var(--ds-type-small)/1 var(--ds-font-body);
  transition: transform var(--ds-duration-instant) var(--ds-ease-snap),
              background var(--ds-duration-control) var(--ds-ease-mechanical);
}
.button:active { transform: translate(2px, 2px); }
.button:focus-visible { outline: 2px solid var(--ds-focus); outline-offset: 3px; }
.button:disabled { opacity: .45; cursor: not-allowed; }
```

Use one signal button per action group. Secondary actions use paper, ink, or ghost variants.

### Text field and textarea

**Anatomy:** persistent label, control, optional help/error text, optional count.  
**Rules:** never rely on placeholder text as the label; use a 1px resting rule and a 2px focus rule; supporting metadata uses mono type.  
**States:** resting, hover, focus, disabled, read-only, error, and success. Error must include text and `aria-describedby`, not color alone.

Textarea content uses body type and at least 144px initial height. Avoid rounded container-within-container styling.

### Tabs

Use a shared horizontal rule with a 2px active segment. Tabs are text-led and square; do not use floating pills. Support arrow-key navigation, Home/End, Enter/Space where the implementation pattern requires activation, and expose the selected state with `aria-selected`.

### Notice

**Variants:** neutral, information, warning, danger, success.  
**Anatomy:** semantic title, short description, optional action.  
**Treatment:** strong left or top rule, flat surface, no diffuse shadow. Status must be readable without an emoji or hue.

Use clean paper text on information and success, carbon on warning and signal red, and ink on neutral paper.

### Metric

An oversized value is the first read, a compact mono label is second, and an optional proportional rule is third. Metrics may sit directly on the section surface or inside a paper/ink field; do not automatically turn each value into a rounded dashboard card.

### Tag

Tags use metadata type at 10–12px, a 1px border, and compact horizontal padding. Pills are allowed because tags are small categorical controls. Category color may tint the border and a subdued fill, but the label must retain accessible neutral text.

### Back link

A back link remains an anchor, uses a text label rather than icon-only navigation, and shifts laterally by no more than 4px on hover. The icon, when present, is decorative. Focus uses a 2px outline.

### Primary CTA

Use one signal-red CTA per composition. It should be flat, high-contrast, and immediately legible. Do not use a red gradient, radial glow, or soft elevation. A hard ink or red registration shadow is allowed when it is the section's single dominant disruption.

### Navigation

Navigation is compact and institutional: metadata or small body type, strong divider, and limited height. It remains subordinate to the display headline. On mobile, preserve clear labels and touch targets; do not reduce navigation to unexplained symbols.

## 9. Media rules

Images are optional evidence or subject matter. The interface must remain compositionally complete when they are unavailable.

- Prefer documentary subject matter, architectural mass, crowds, faces, mouths, or political context where appropriate to the product.
- Prefer grayscale, high contrast, threshold, halftone, or restrained duotone treatment.
- Use 1:1, 4:5, 4:3, or 16:9 crops. Avoid unexplained bespoke ratios.
- Use hard crops that prioritize the intended subject. Do not add soft cinematic fades around every image.
- Keep text in HTML. Do not place essential copy, labels, or controls inside bitmap assets.
- Never depend on a hero image to provide the page's headline, texture, contrast, or primary color.
- Provide meaningful alternative text when the image contributes information; use empty `alt` only for genuinely decorative media.
- At small widths, a significant media field may become edge-to-edge while text keeps a safe gutter.

## 10. Responsive behavior

### Invariants

- The institutional → emotional → explanatory hierarchy remains intact.
- Display type remains oversized and condensed.
- Contrast, reading order, and minimum target sizes do not change.
- Carbon, paper, ink, and signal roles remain semantic.

### What changes

- Twelve columns become eight at 768px and four below it.
- Editorial overlap flattens below 1024px.
- Split layouts become one column below 768px.
- Copy and media reorder only when the DOM order already supports a correct reading sequence.
- A contrasting material or media layer may bleed to the viewport edge on mobile.
- Section spacing compresses through fluid tokens; it does not collapse to arbitrary small values.
- Metadata wraps. It is not hidden solely to make a composition fit.
- Display headlines may reduce from roughly 10rem to 4rem, but retain tight leading and dominance.

### Reference checks

- **390px:** four-column sequence, 16px gutter, edge bleed allowed, no overlap, 44px targets.
- **768px:** eight-column grid, 24px approximate gutter, split layout permitted when content remains readable.
- **1024px:** twelve-column editorial grid activates; overlap limited to one column.
- **1440px:** container stops at its width token; additional space becomes margin rather than longer text lines.

## 11. Accessibility

- Meet WCAG 2.2 AA contrast for all normal text and interactive states.
- Use the approved color pairs in this document; retest any new pair.
- Focus indicators are at least 2px and visually separate from component borders.
- Controls have a minimum 44×44px target even when their visible shape is smaller.
- Do not encode status, category, or selection through color alone.
- Decorative pseudo-elements use `pointer-events: none` and carry no accessible content.
- Grain and halftone must not reduce the contrast of text or focus indicators.
- Respect `prefers-reduced-motion`; reduce transitions to effectively immediate without hiding the final state.
- In forced-colors mode, remove texture and duotone overlays and restore strong system-color borders.
- Preserve semantic heading order even when visual scale is intentionally irregular.
- Use `text-wrap: balance` only for short headings, never paragraphs or data.

Reduced-motion baseline:

```css
@media (prefers-reduced-motion: reduce) {
  .ds-motion {
    scroll-behavior: auto;
    animation-duration: 1ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 1ms !important;
  }
}
```

## 12. Extension and governance

Before adding a token, primitive, or component variant:

1. Confirm an existing semantic role cannot express the requirement.
2. Confirm the need recurs in at least two contexts.
3. Name the addition for its role, not its current page or visual value.
4. Define light/dark contrast, focus, disabled, reduced-motion, and responsive behavior.
5. Add a plain HTML/CSS example.
6. Record the decision and increment the system version.

Do not add page-specific tokens such as `--homepage-red-card` or value-specific tokens such as `--gray-17`. Prefer `--ds-surface-signal` and `--ds-text-secondary`.

### Release discipline

- Patch: documentation corrections or non-visual fixes.
- Minor: backward-compatible token, primitive, or component additions.
- Major: renamed/removed tokens, changed class contracts, or meaningfully different art direction.

## 15. Repository audit appendix

This appendix records the environment from which the system was derived. It is historical context, not required to implement the design system.

### Directly observed

- The project already separates Vue pages, reusable transcript/video components, stores, and a global stylesheet.
- Existing global variables cover a dark palette, three font roles, two radii, and a small set of surfaces.
- Character is concentrated in an image-led landing hero; most remaining UI uses conventional dark cards, gradients, rounding, and soft shadows.
- Signal red, noise, spacing values, transition timings, and component treatments are repeated in scoped styles.
- Responsive behavior is mostly a single 768px collapse.
- Existing references consistently show condensed type, black/paper/red contrast, tactile print processes, hard crops, and editorial asymmetry.
- Handwritten evidence or detective-notebook notation is not a consistent reference signal.

### Inferred

- A political print laboratory best reconciles the project's analytical subject with its confrontational references.
- Brand red should remain distinct from data-classification colors.
- Material character is more portable when expressed through shared CSS layers than through page-specific imagery.
- Existing functionality can adopt the system gradually without an architecture rewrite.

### Proposed

- Adopt the prefixed foundations and primitives in new work.
- Migrate existing surfaces only when they are actively redesigned.
- Keep the system documentation portable and framework-independent.
- Require future deviations to pass the governance checklist.

## 16. Known repository inconsistencies

The following are outside the 1.0.0 foundations release:

- legacy raw color and spacing values remain in scoped page CSS;
- the existing noise SVG is duplicated rather than using the new grain primitive;
- rounded SaaS-style cards and gradients remain on current pages;
- label colors exist in more than one data shape and language taxonomy;
- motion values and focus treatments are not yet unified;
- mobile behavior is limited on legacy routes;
- the landing hero still depends on a bitmap for much of its character;
- dormant video UI does not match the active backend scope;
- the current installed frontend dependencies do not resolve declared `pinia` until dependencies are restored.

Address these through deliberate page migrations. They do not change the portable system contract above.
